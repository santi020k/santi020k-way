# Local hardening audit — 2026-10-12

Target: `release/v0.1.0`. Claude Code performed a read-only review of the CLI, setup and rollback,
catalog/MCP, plugin generation, hooks, release/deployment scripts, website, and tests. Findings
were independently checked before implementation. No publication or deployment was performed.

## Implemented improvements

- Setup now rejects proposed instruction files exceeding 1 MiB before writing references or
  backups. Regression coverage includes multibyte input, unchanged personal content after rejection,
  and installation/update/rollback at exactly the supported limit.
- Instruction replacement preserves original permissions despite the process umask. Installation
  and rollback tests use a restrictive umask and verify private backup permissions.
- Website generation removes retired sources and templates. Temporary-directory tests cover
  repeated builds and preservation of unrelated static assets; Turbo tracks the extracted helper.
- Release publication verifies GitHub release state and existing payloads before publishing npm.
  Mocked-provider subprocess tests cover incomplete releases, provider failures, conflicting npm
  provenance, successful publication, and retries after npm/GitHub command failures without
  touching external services.
- Artifact checks validate both generated marketplaces, their plugin listings, metadata, policies,
  and source paths. Claude's native validator also accepted the plugin and marketplace.
- CLI commands report missing queries and IDs accurately, reject explicitly empty approval hashes,
  and reject setup-only options even when their values are empty. Subprocess tests cover command
  routing, errors, catalog output, and temporary-home setup/rollback for both agents.
- Browser search-reset coverage derives the expected count from the catalog rather than a fixed
  entry count.

## Review dispositions

Claude's marketplace-validation and CLI-error findings were accepted and addressed above. Its
claim that `actions/checkout` omits tags with `fetch-depth: 0` was rejected: the
[official checkout documentation](https://github.com/actions/checkout#fetch-all-history-for-all-tags-and-branches)
explicitly documents fetching all branches and tags with that setting, which the release workflow
already uses. No workflow change was needed for that finding.

A fresh review highlighted partial publication when GitHub creation fails after npm succeeds.
The suggested order reversal was not adopted: it moves the partial-success boundary to the other
provider rather than making the operations atomic. Regression tests demonstrate that retrying the
same commit completes GitHub creation without republishing the existing npm version, and that npm
command failure prevents GitHub creation. The claim that this necessarily causes permanent
divergence was rejected against those executable recovery tests. The release plan now documents
this boundary and recovery sequence explicitly.

Lower-confidence observations were also checked. Claude plugin/marketplace metadata passed native
validation. Rejecting prerelease Quality versions remains consistent with the stable-tool policy.
The fixed catalog-count observation was addressed in the browser test. Existing filesystem
check/write race limitations were not presented as a reproduced vulnerability or a new guarantee
for hostile shared directories; symlink and installer-lock tests remain in place.

## Verification boundary

The local completion gate is `pnpm verify`: policy, zero-warning lint, type checks, behavioral tests,
builds, artifact checks, document formatting, browser tests, and release archives. Both plugin
archives were additionally extracted into temporary physical directories and their bundled CLIs
were exercised through setup and rollback, including permission preservation. These checks do not
establish hosted CI, npm publication, GitHub release, or production deployment success.
